# REVIEW.md

Review of the starter `app/main.py`. "Where" refers to the starter's functions.

| # | Where | What is wrong | How you'd notice it | How I fixed it |
|---|---|---|---|---|
| 1 | `health` | Always returns 200, never talks to MongoDB. | Stop MongoDB; `/health` still says `ok`, so a runner starts testing a dead service. | `ping` the database; 503 when it fails. |
| 2 | `create_employee` | Check-then-insert (`find_one` then `insert_one`) with no unique index: two parallel creates both pass the check. | 20 parallel `POST /employees` with the same code give several 201s and duplicate rows. | Unique index on `emp_code`, created at startup; `DuplicateKeyError` -> 409. |
| 3 | `EmployeeIn`, `PunchInIn` | No validation: any `emp_code`, email, `shift_start="banana"`, equal start/end, `joined_on="2026-02-30"`; punch-in `status` is any string (`"ABSENT"`, `"x"` get stored). | `POST /employees` with `{"shift_start":"9:30"}` returns 201 and later breaks `split(":")`/late maths. | Pydantic models with strict types and regex/date validators, `shift_start != shift_end`, status limited to PRESENT/WFH/ON_DUTY. Bad input -> 422. |
| 4 | `create_employee` | `created_at = datetime.now()` is naive *local* time (not UTC) and the response returns a datetime string, not epoch ms. | Response `created_at` is `"2026-07-06T10:15:00.123456"`; contract says integer ms. | UTC datetime stored, epoch-ms integer returned. |
| 5 | `list_employees` | `skip = page * page_size` skips the whole first page. | `GET /employees?page=1` never returns the first employees. | `skip = (page-1) * page_size`. |
| 6 | `list_employees` | `total` counts the whole collection, ignoring `department`; no sort so paging is unstable; `page=0`, `page_size=0/-5/100000` are accepted. | `?department=HR` returns 3 items but `total: 700`. | Count uses the same filter; sort by `emp_code`; `page>=1`, `1<=page_size<=100` (422 otherwise). |
| 7 | `compute_late_minutes` | Four bugs: (a) `replace(hour=..)` on the punch-in's own (UTC/naive) clock, not IST; (b) shift start is taken from the punch-in's calendar day, so overnight shifts are wrong; (c) `int(seconds/60)` floors first, then `> 10`: 09:40:30 becomes 10 and is *not* late (should be late, 10); (d) seconds are not truncated. | Shift 09:30, punch-in 09:40:01 IST returns 0 (contract: 10). Server in UTC: every IST punch is hours "late". | Convert to IST, shift start anchored on the attendance date, compare in seconds: `delta > 600` then `delta // 60`. |
| 8 | `compute_work_hours` | Python `round()` is float + banker's rounding, contract wants half-up. | 54 s = 0.015 h gives 0.01 (expected 0.02). | Integer half-up: `(2*sec*100 + 3600) // 7200`. |
| 9 | `compute_overtime` | No 30-minute minimum (returns 1..29); ignores overnight shifts (end always on `date`); mixes an aware IST datetime with a naive punch-out, which raises `TypeError`. | Out 18:45 on shift end 18:30 returns 15 (contract: 0). Overnight 06:40 out returns a negative-clamped 0. | Shift end on the next day for overnight shifts, floor minutes, `>= 30` else 0, everything timezone-aware. |
| 10 | `punch_in` | Unknown employee: `emp` is `None`, `emp["shift_start"]` raises -> 500. | `POST /attendance/punch-in {"emp_code":"NOPE"}`. | 404 before anything else. |
| 11 | `punch_in` | Time handling: `datetime.fromtimestamp(ms/1000)` uses the server's local zone and gives naive values; the date is the server-local date, not IST (R1); overnight rule (R1) missing; milliseconds not truncated; `if body.punched_at` treats 0 as "missing"; seconds-looking, float, negative or huge values are accepted (huge raises `OSError` -> 500). | `punched_at: 1783312500` (seconds) stores a 1970 date. | `StrictInt` bounded to 1e11..4.1e12 (422 otherwise), conversion to UTC, truncation to seconds, `attendance_date()` implements R1 in IST. |
| 12 | `punch_in` | Same check-then-insert race as #2. | Two parallel punch-ins both return 201 and create duplicate records. | Unique `(emp_code, date)` index; `DuplicateKeyError` -> 409. |
| 13 | `punch_in` response | Leaks the internal `id` (ObjectId) and returns datetimes, not epoch ms; `half_day`/`history` shape differs from the contract. | Response has `"id": "665f..."` and ISO strings. | One serializer `record_out()` used by every endpoint (no `_id`, ms integers). |
| 14 | `list_attendance` | Loads the entire collection into memory and sorts/paginates in Python; sorts by `date` only (no `emp_code` tiebreak, so unstable); `page=0` makes a negative slice; `total` is `len(all docs)`. | 100k records: slow and memory-heavy; `?page=0` returns wrong rows. | Query filter + `sort` + `skip/limit` in MongoDB, `count_documents` on the same filter, validation of `page`/`page_size`. |
| 15 | `list_attendance` | Filters not validated: `status=banana`, `date_from="x"`, and `date_from > date_to` all run; `_id` leaked as `id`. | `?date_from=2026-07-09&date_to=2026-07-01` returns 200 with nothing. | Enum for status; date format check; `date_from > date_to` -> 422. |
| 16 | whole file | No indexes at all, so every query is a collection scan. | `explain` shows COLLSCAN; list gets slow at 100k. | `ensure_indexes()` at startup (idempotent), see DECISIONS.md. |
| 17 | `MongoClient(...)` | Not `tz_aware`, so PyMongo returns naive datetimes; comparing them with aware ones raises `TypeError`. No server-selection timeout (30 s hang when MongoDB is down). | `TypeError: can't subtract offset-naive and offset-aware datetimes`. | `tz_aware=True, tzinfo=UTC`, `serverSelectionTimeoutMS=5000`; naive values are still handled by `as_utc()`. |

**Looked at and decided not to change**
- `load_dotenv()` does not override real environment variables, which is what the contract asks for.
- Endpoints are plain `def` (run in FastAPI's threadpool), so the blocking PyMongo calls do not block the event loop. I kept PyMongo (sync) on purpose.
- Comparing `date` strings with `$gte/$lte` is correct because `YYYY-MM-DD` sorts chronologically.
- The helpers were not reused as-is: #7, #8, #9 show why; I rewrote them as pure functions (`compute_late_minutes`, `compute_work_hours`, `compute_overtime`) and added `derive_fields()` so punch-in, punch-out and correction all share one implementation.
